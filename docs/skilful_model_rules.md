## 1. СТ — САКРАЛЬНАЯ точка (Point SP / SP1 / SP2)  [CalcSP, TModel.cs:899]
СТ = точка, где **линия тренда (ЛТ) и линия целей (ЛЦ) ВСТРЕЧАЮТСЯ** (пересечение).
- `PointSP`  = CrossLines(ЛТ, ЛЦ)            — по экстремумам;
- `PointSP1` = CrossLines(ЛТ, ЛЦ')           — по т2' (коррект. по телам);
- `PointSP2` = CrossLines(ЛТ-касат, ЛЦ-касат) для МП; = PointSP1 для МР/МДР.
- DT СТ ставится по бару пересечения (CalcSP:922-928).

**Смысл:** «сакральная» — финальная точка схода линий. **Дальше СТ модель не продлевается.**
- **МП (Attraction):** ЛТ-касат и ЛЦ-касат **сходятся к СТ в будущем** → СТ это правый апекс; за СТ — ничего.
  (Model.cs:220-222 — `LastPoint = PointSP2`, обе линии заканчиваются в СТ.)
- **МР (Expansion):** СТ — **левый апекс**, от него линии **расходятся** вправо к целям.
  (Model.cs:125-126 — построение начинается ОТ `PointSP2`.)

### 1.1. ТИП модели = по углам ЛТ/ЛЦ  [CalcModelType, TModel.cs:828-889]
Сравниваются |угол ЛЦ| и |угол ЛТ|:
- **|ЛЦ| > |ЛТ|** → **МР** (Expansion): ЛЦ круче, линии **расходятся** → СТ = пересечение = **близкий левый апекс**.
  Именно здесь «ЛЦ и ЛТ пересекаются и образуют СТ» (видимый апекс) — **признак МР**.
- **|ЛЦ| < |ЛТ|** → **МП** (Attraction): ЛТ круче, линии **сходятся** вперёд → СТ = правый апекс.
- **равны** → **МДР** (Balance).
- Доп. ПЕРЕКЛАССИФИКАЦИЯ в МДР: если апекс СТ слишком далеко —
  МР→МДР при `(т1.Бар − SP1.Бар) ≥ (т4−т1)·MBSize1` или `SP1.Бар > SP.Бар`;
  МП→МДР при `(SP1.Бар − т1.Бар) ≥ (т4−т1)·MBSize2`.
  Т.е. **МДР = вырожденный МР/МП** (СТ-апекс далеко, линии ~параллельны — «равновесие»).
- ⚠️ Веер даёт НЕСКОЛЬКО моделей на одном т1 (разных типов!). Для рисунка/сверки брать **совпавшую с эталоном**
  (по типу+точкам), а не первую из веера.

### 2.2. ШТРИХ-точки (1'/2'/3'/4') — ПО КАКИМ ПРАВИЛАМ  [DrawSelectedModelLables 900-965]

(NB: рисуется именно **Point23**, не Point21!) Определяются ДВУМЯ механизмами:

**A. Коррекция по линии целей** (вершину двигают на бар, сильнее всех ПРОБИВАЮЩИЙ линию):
- **т2' (Point21)** [CalcTargetCorrected 942-993]: идём от т2 **назад к т1**; если бар своим High(up)/Low(dn)
  пробивает линию ЛЦ'(т2'–т4) → т2' на него, ЛЦ' пересчитывается. Левая граница — по ТЕЛУ т1 (Open vs Close).
- **т3' (Point31)** [CalcPoint3Corrected 1042-1129]: идём от т3 **вперёд к т5**; если бар пробивает линию
  ЛЦ-MA(т3'–т5) → т3' на него. Если т5 ещё нет (Bar==0) → т3' пусто.

**B. Коррекция по КАСАТЕЛЬНОЙ огибающей** [CalcTangentLines 2595-2724] — прямые, охватывающие ВСЁ движение
т1→т4; штрих = бар КАСАНИЯ огибающей:

- **т2-касат (Point23)** = касание касательной ЛЦ на участке т1→т2' (старт = т2' по телу);
  **т4' (Point41)** = касание касательной ЛЦ на участке т2'→т4.
- Порог значимости т4': `|т4.Бар − т4'.Бар| ≥ 3` → ошибка 0x1000 (§2 выше).

**Условия отрисовки** (DrawSelectedModelLables): 1'/2'/4' — если `Point{11,23,41}.X != Point{1,2,4}.X`;
**3'** — строже: `Point31.X > т3.X И т5.X > т3.X И т5.X ≠ т4.X` (стр.947-957), вместе с подписью «5».

**Golden-реконструкция:** доступен только **4'≈** (по огибающей лоёв/хаёв); 1'/2'/3' требуют движок.

## 3. ВРЕМЯ ЖИЗНИ модели  (LifeTime = MaxProcessBar)  [TModel.cs:96, 739-745]
Комментарий в коде: «(СТ-4)*2 от 4 == время жизни модели». Это горизонт «до определённого плана» —
докуда модель живёт и докуда тянутся цели.
**ВАЖНО: считается по ВРЕМЕНИ (номер бара), НЕ по цене.** Берутся `.Bar` точек (индексы баров),
округлённые `Math.Round` (банковское). Результат — НОМЕР БАРА (горизонт по времени):
- **МР:**  MaxProcessBar = round(т4.Бар) + 4·(round(т4.Бар) − round(СТ(SP2).Бар))   [SP_P4x4 = 4]
- **МП:**  MaxProcessBar = round(SP1.Бар) + 2·(round(SP1.Бар) − round(т1.Бар))       [HP_P1x2 = 2]
- **МДР/проч.:** MaxProcessBar = round(т4.Бар) + 4·(round(т4.Бар) − round(т1.Бар))   [P1_P4x4 = 4]
- (Цена в LifeTime не участвует. Цену уровней дают §4 (100/200%) и §6 (Targets).)
- Модель обрабатывает бары, **пока `Bar.Bar > MaxProcessBar`** (TModel.cs:1811, 1915) — затем умирает.
- Все целевые линии тянутся вправо **до LifeTime** (`Targets[*].xb = LifeTime`).

## 6. Цели — должно быть **5 целей + НР**  [CalcTargets, TModel.cs:2139; массив Targets[0..5]]
**ВАЖНО:** по методологии целей **пять + НР**. В текущей сборке Skilful активны только Target0..2,
а Target3..5 **закомментированы** (TModel.cs:2156-2166) — поэтому golden-данные содержат урезанный набор,
но полные правила такие:
- **МР / МДР:**
  - Target0 = (слом ЛТ + первое касание ЛТ − т6); бар = слом ЛТ;
  - Target1 = **т1** (xb = LifeTime);
  - Target2 = **2·т1 − т4** (отражение т4 через т1; xb = LifeTime);
  - Target3 = **2·(первый пробой ЛЦ) − т3**   *(в сборке закомм.)*;
  - Target4 = **2·(первый пробой ЛЦ) − т1**    *(закомм.)*;
  - Target5 = **2·(первый пробой ЛЦ) − СТ**    *(закомм.)*.
- **МП:**  Target0 = 2·т1 − СТ;  Target1 = СТ  (оба xb = LifeTime).
- **НР (Point61)** — расчётная НР (т6расч), отдельная цель; от неё считаются 100%/200% (§4),
  достижение фиксируется флагом `HPreached` (§7).

**Итог (подтверждено): 5 целей = Target1..Target5, + НР.**
(`1*/2*/3*` на чарте — это ТОЧКИ т1'/т2'/т3', НЕ цели; см. §2.1. Цели на чарте могут не рисоваться.)
Target0 — служебный уровень от слома ЛТ (не входит в «пятёрку»). В текущей сборке Target3..5 закомментированы,
поэтому golden даёт неполный набор — для полной модели нужны все 5 + НР.

## 10. РАСЧЁТ (calc) vs ОТРИСОВКА (visual) — НЕ ПУТАТЬ + как логически определить модель
**Главный принцип отладки:** различать (а) баг РАСЧЁТА — движок даёт не те числа/вершины vs эталон;
(б) баг РИСОВАЛКИ — модель верная, но нарисована не так (напр. «тип #5»: ta_draw брал не ту модель веера);
(в) **ОСОБЕННОСТЬ ПОСТРОЕНИЯ** — выглядит «неправильно», но это легитимное поведение алгоритма (НЕ баг).
**Рисовалка, получив верную модель, даёт верное.** Главная ловушка — принять особенность ПОСТРОЕНИЯ за баг.
Поэтому: если что-то «смотрится не так» — НЕ гадать, а **идти и реально читать C#-код** (TModel/ModelsManager),
сверять построчно, и только подтверждённое расхождение порт-vs-C# считать багом. (Проверка эта сессия: 4 «подозрения»
агентов оказались особенностями/верным кодом, не багами — см. §10.5.)

### 10.1 Реальные точки т1..т6 — КАРДИНАЛЬНО на экстремумах

### 10.3 Определение ТИПА (логически)  [CalcModelType, §1.1]
1. Построить ЛТ (через т1,т3) и ЛЦ' (через т2',т4) → их углы.
2. **|ЛЦ| > |ЛТ|** → кандидат **МР** (расходятся, СТ — близкий левый апекс ЛТ×ЛЦ).
   **|ЛЦ| < |ЛТ|** → кандидат **МП** (сходятся к СТ справа). **равны** → **МДР**.
3. Переклассификация в **МДР**, если СТ-апекс далеко: МР→МДР при `(т1−SP1).Бар ≥ (т4−т1)·3` или `SP1.Бар>SP.Бар`;

4. **СТ как ЛТ×ЛЦ-апекс с подписью «CP» рисуется ТОЛЬКО у МР** (Model.cs:156). У МП СТ — правый конец линий (без метки), у МДР СТ не используется.

   (внутренние/для графика). → для точного рисунка брать **полную модель из движка**, а не из .xls.
